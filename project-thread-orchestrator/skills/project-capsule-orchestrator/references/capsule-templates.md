# 项目胶囊模板

在项目根目录创建或完善项目胶囊。先读取现有文件，保留有证据的内容和用户编辑；按需增量更新，不盲目覆盖。所有事实使用证据状态：`VERIFIED`、`USER_CONFIRMED`、`INFERRED`、`UNKNOWN`、`NEEDS_TEST`、`REJECTED`、`CONFLICTED`。

## 基础文件

### `AGENTS.md`

只记录跨里程碑长期适用的规则，不写一次性任务细节。

```markdown
# 项目协作规则

## 开始任务前
- 读取：SPEC.md、PLAN.md、STATUS.md、DECISIONS.md、RISKS.md。
- 读取 THREADS.md 与自身任务卡。
- 核对前置依赖、允许路径和安全门。

## 修改边界
- 仅修改当前任务卡允许的路径。
- 不覆盖或回滚无法归属的现有修改。
- 危险操作必须取得明确人工批准。

## 验证
- 运行任务卡列出的验证命令。
- 记录命令、结果和未验证项。
- 不把计划、推断或未运行测试写成完成。

## 禁止
- 不自动操作真实硬件、生产系统或敏感数据。
- 不自动提交或推送 Git。
- 不自动进入下一里程碑。

## 完成后
- 更新 STATUS.md、相关决策与风险。
- 更新 THREAD_REGISTRY.md 中本线程的状态和时间。
- 达到验收标准后停止并等待用户。
```

```markdown
- [触发、行为、期望结果；证据状态]

## 目标
- [可验证目标]

## 非目标
- [明确不做的内容及原因]

## 功能需求
- FR-001：[需求；验收方式；证据状态]

## 非功能需求

## 成功指标

## 最终验收标准

## 已知未知项
- [UNKNOWN/NEEDS_TEST/CONFLICTED；影响；解决方式；责任里程碑]
```

### `DECISIONS.md`

为每个决策追加独立记录，不静默重写历史。

```markdown
## DEC-001 [标题]

- 日期：[ISO 8601 日期]
- 状态：[proposed/accepted/superseded/rejected]
- 背景：[事实与约束]
- 候选方案：[方案及关键权衡]
- 最终决定：[明确决定；尚未决定时写 UNKNOWN]
- 原因：[与目标、风险和证据的关系]
- 影响：[受影响的文件、接口、里程碑或运维]
- 可逆性：[高/中/低；回退方式]
- 重新评估条件：[触发信号]
- 证据：[文件、测试、用户确认或实验]
```

### `THREAD_REGISTRY.md`

插件创建前将真实 thread ID 写为 `—`，不得生成占位假 ID。插件返回后仅写入真实 ID。

```markdown
# 线程注册表

| ID | 名称 | 状态 | 前置依赖 | 关键路径 | 允许并行 | 执行模式 | 阻塞原因 | 真实 thread ID | 最近更新时间 |
|---|---|---|---|---|---|---|---|---|---|
| M0 | [名称] | DRAFT | — | 是 | 否 | readonly | 等待用户确认 | — | [ISO 8601] |
```

“允许并行”由依赖与文件范围共同决定，不能仅根据 `parallel_group` 推断。

### `.project-capsule/`

将机器可读状态放入此目录，至少包含经 schema 验证的 `thread-plan.json`。可按需保存：

- 线程计划版本与摘要哈希；
- 插件预览回执；
- 创建/同步结果；
- 审计证据索引。

不得在其中保存凭据、秘密值或伪造的线程 ID。保留用户已确认计划的不可变副本或哈希，以便创建时核对。

## 更新纪律

- 写入前验证事实；为每条状态保留证据。
- 将“计划”“正在进行”“已完成”严格分开。
- 里程碑未满足验收标准时不得标记 `DONE`。
- 发现冲突时使用 `CONFLICTED`，不静默选择有利版本。
- 每个线程结束时只更新与其输出和证据有关的胶囊部分。
- 插件工具不可用时保留计划，将注册表维持在未创建状态。
