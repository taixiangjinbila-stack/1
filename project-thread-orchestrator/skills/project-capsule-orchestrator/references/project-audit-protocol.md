# 项目事实审计协议

使用本协议识别项目类型、建立证据基线并发现虚假进度。规划阶段只执行安全、只读或不改变项目语义的本地检查。

## 1. 确认项目边界

先确认：

- 当前工作目录真实存在；
- 当前目录是专用项目目录；
- Git 仓库根目录及当前工作目录的关系；
- 当前分支、工作树状态和未提交修改；
- 是否位于 Codex 临时 worktree；
- 是否存在多个版本、重复目录或散落文件；
- 是否存在 `AGENTS.md`、项目胶囊、`RECOVERY.md` 和线程注册信息；
- 线程创建插件所需逻辑工具是否可发现。

若项目目录等于 Windows 盘符根目录（如 `C:\`、`D:\`）、POSIX 根目录 `/` 或其他卷根目录，立即停止。建议用户选择或创建专用项目文件夹；不得在磁盘根目录生成胶囊或线程计划。

不得仅凭文件夹名称判断项目根目录。优先使用 Git 根目录、构建配置和项目文档交叉确认。

## 2. 识别项目类型

选择最符合当前事实的一种主类型，并记录附加风险标签：

- 全新项目：没有可审计实现，主要工作是定义目标和验证假设。
- 已有且较健康的项目：文档、实现、测试和历史基本一致。
- 历史接手项目：上下文或维护者知识缺失，但资产仍可辨认。
- 恢复项目：多个线程、版本或错误假设导致状态冲突，无法信任完成声明。
- 高风险硬件项目：涉及真实电源、执行器、烧录、机械运动或设备损坏风险。
- 生产或敏感数据项目：涉及生产写入、隐私、凭据、受监管数据或外部用户影响。

高风险硬件、生产和敏感数据可作为其他类型的附加标签；它们必须触发人工安全门。

## 3. 读取顺序

在提问前，按可用性读取：

1. 项目范围内适用的 `AGENTS.md`；
2. `README*`、架构说明和项目文档；
3. `SPEC.md`、`PLAN.md`、`STATUS.md`、`DECISIONS.md`、`RISKS.md`；
4. `RECOVERY.md`、`FUTURES.md`、`THREADS.md`、`THREAD_REGISTRY.md`；
5. 构建、依赖、lint、类型检查和测试配置；
6. 源代码结构、入口、核心接口和迁移文件；
7. Git 状态、分支和相关历史；
8. 已有测试、测试结果和可复现产物；
9. 已有线程或任务注册信息。

只读取与项目审计有关的内容。尊重更具体目录中的 `AGENTS.md`。

## 4. 建立证据账本

为重要陈述记录：

| 字段 | 要求 |
|---|---|
| 声明 | 可单独验证的事实或假设 |
| 状态 | `VERIFIED`、`USER_CONFIRMED`、`INFERRED`、`UNKNOWN`、`NEEDS_TEST`、`REJECTED` 或 `CONFLICTED` |
| 来源 | 文件路径、提交、命令、测试结果或用户确认 |
| 时间 | 证据获取或确认时间 |
| 影响 | 对目标、风险、依赖或完成状态的影响 |
| 后续 | 需要的测试、提问或决策 |

仅在证据可复现时使用 `VERIFIED`。文档中的“完成”属于待验证声明，不自动构成证据。一次成功运行只证明该环境下该命令当时成功。

## 5. 审计检查表

### 文档与实现

- 检查代码是否实现文档宣称的核心行为。
- 检查接口、配置、数据模型和部署说明是否一致。
- 查找过期路径、失效链接、占位符和未完成标记。
- 检查旧聊天或计划中的假设是否仍然成立。

### 完成声明与可复现性

- 为每个“已完成”声明寻找实现、测试或可运行证据。
- 检查生成产物能否由记录的命令重建。
- 区分演示通过、局部通过和最终验收通过。
- 将不可复现结果标记为 `NEEDS_TEST` 或 `CONFLICTED`。

### 工程基线

- 识别受支持的构建、lint、类型检查和测试命令。
- 在成本合理且不写入外部系统时运行安全检查。
- 记录命令、退出码、关键输出和环境限制。
- 检查测试是否覆盖核心行为，而不只统计文件或用例数量。
- 不为获得“绿色结果”而修改代码、降低阈值或跳过失败。

### 工作树与版本

- 记录当前分支、HEAD 和未提交修改。
- 将现有修改视为用户资产，不回滚、不覆盖。
- 识别重复实现、废弃分支线索和无法归属的生成文件。
- 不自动提交、切换分支、合并、变基或推送。

### 安全与恢复

- 查找硬编码凭据、明文令牌和危险默认配置，但不要在报告中复述秘密值。
- 检查最小权限、输入验证、隔离、备份和回滚能力。
- 检查日志、监控、告警、故障恢复和数据保留策略。
- 检查生产写入、迁移和删除是否有预演与停止条件。
- 检查硬件电气限制、急停、联锁、隔离和安全测试缺口。
- 检查第三方依赖、供应链、许可证和单点故障风险。

### 技术债与架构

- 识别高耦合核心文件、隐式接口和重复逻辑。
- 识别高迁移成本决策和不可替换依赖。
- 区分阻塞关键路径的债务与可延后优化。
- 不把代码风格偏好升级为项目级风险。

## 6. 允许与禁止

允许：

- 读取文件、目录和版本信息；
- 查询 Git 状态和历史；
- 运行已存在的本地只读检查；
- 运行不会访问生产、真实硬件或敏感外部服务的构建与测试；
- 在项目胶囊中记录审计结果。

规划阶段禁止：

- 删除、移动、覆盖或回滚用户文件；
- 安装系统软件或修改系统设置；
- 给真实硬件上电、烧录或驱动执行器；
- 触碰生产系统或向外部服务写入；
- 导出、上传或暴露敏感数据；
- 提交、推送、合并、变基或清理 Git；
- 为验证而改变业务实现。

若命令的副作用不明确，先将其列为 `NEEDS_TEST`，设计隔离验证步骤，不直接运行。

## 7. 输出审计摘要

至少输出：

- 项目根目录与项目类型；
- 已验证事实及证据；
- 用户确认事实；
- 冲突、未知和待测试项；
- 未提交修改与版本风险；
- 虚假或不可验证完成声明；
- 工程基线结果；
- 主要安全、恢复和架构风险；
- 对里程碑顺序和安全门的影响。

不把计划写成完成，不把推测写成事实，不因检查未运行而声称检查通过。
