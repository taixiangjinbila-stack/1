# 战略路线与前瞻分析

对复杂项目使用本协议寻找比“继续堆功能”更可靠的路径。不要因用户要求创新就增加不必要的技术、代理、服务或硬件。

## 何时使用只读 subagents

仅在项目复杂、证据分散或风险跨多个领域时，使用最多四个只读 subagents。为每个 subagent 指定边界明确的探索任务、可读范围和输出问题；禁止其修改文件、调用生产、操作硬件或创建线程。

可选角色：

### 现实审计者

寻找：

- 看似完成但缺少实现或验收证据的部分；
- 虚假进度和不可复现结果；
- 测试没有覆盖的核心声明；
- 文档、代码与 Git 历史的冲突。

### 架构未来学家

寻找：

- 扩展瓶颈和高迁移成本决策；
- 单点故障、不合理耦合和隐式接口；
- 可能形成共享平台能力的部分；
- 未来替换、扩展和运维的限制。

### 产品挑战者

寻找：

- 当前方案是否解决真实用户问题；
- 是否存在更简单的产品形态；
- 是否把技术手段当成用户价值；
- 哪个最小实验最能验证需求、可用性或付费/采用意愿。

### 风险对抗者

寻找：

- 数据丢失、权限滥用和隐私泄露；
- 硬件损坏和人身安全风险；
- 部署失败与不可恢复操作；
- 供应链、依赖、许可和外部服务风险。

主代理必须核对证据、解决冲突并综合结论。不得机械拼接 subagent 输出，不得把 subagent 推断升级为 `VERIFIED`。

## 三条必备路线

始终提出三条可比较路线。路线可以共享基础里程碑，但必须体现不同的优化目标。

写入机器可读计划时，分别使用 `ROBUST`、`LEVERAGE`、`BREAKTHROUGH`；不得写入中文别名或自定义组合值。组合建议应选择当前首先执行的一条作为 `selected_strategy`，并在决策说明中记录后续阶段门。

### A. 稳健路线

目标：

- 最快建立可信基线；
- 降低失败和恢复成本；
- 优先补齐测试、文档、回滚、安全和可观测性。

适用于事实不清、恢复项目、高风险环境、资源有限或交付可靠性优先的情况。

### B. 杠杆路线

目标：

- 用有限改动获得明显能力提升；
- 优先高复用、高回报的结构性改进；
- 在风险和收益之间保持可验证平衡。

适用于已有可用基线、瓶颈明确且共享能力能服务多个后续里程碑的情况。

### C. 突破路线

目标：

- 重新思考项目边界；
- 探索可能改变产品形态或能力上限的方案；
- 用最小实验验证高潜力假设。

适用于核心价值假设尚可低成本验证、用户容忍探索风险且失败可逆的情况。不得默认推荐。

## 每条路线的固定字段

使用同一结构描述每条路线：

```markdown
### [路线名称]
- 核心思想：
- 解决的根本问题：
- 依赖的假设：
- 预期收益：
- 实施成本：[时间/人力/资金/设备/迁移]
- 主要风险：
- 可逆性：[高/中/低；退出或回退方式]
- 最小验证实验：
- 放弃条件：
- 不应选择的情况：
```

将尚未验证的依赖假设标记为 `INFERRED`、`UNKNOWN` 或 `NEEDS_TEST`。

## 最小验证实验

为每条路线设计尽可能小的验证：

- 只验证最可能推翻路线的关键假设；
- 定义输入、输出、成功阈值和失败阈值；
- 限制时间、数据、硬件和成本暴露；
- 保持可逆并避免生产写入；
- 指定证据保存位置和责任里程碑；
- 达到放弃条件时停止，不扩大实验。

突破路线必须先有验证实验，不能直接成为大规模实现承诺。

## 推荐方法

根据以下因素给出推荐，不按“创新程度”排序：

- 用户目标与成功指标的匹配度；
- 风险承受能力和不可逆损失；
- 时间、预算、人力、设备和维护能力；
- 当前项目成熟度与事实可信度；
- 关键假设的验证成本；
- 回退能力和依赖锁定；
- 对关键路径的影响。

明确说明推荐理由、未选路线的主要代价和重新评估条件。可以推荐组合路线，例如“先用稳健路线建立基线，再执行杠杆实验”；必须指出阶段门。

## 写入项目胶囊

- 将完整路线比较写入 `FUTURES.md`。
- 将选定路线、理由和重新评估条件写入 `DECISIONS.md`。
- 将路线依赖假设写入 `SPEC.md` 或 `STATUS.md`。
- 将最小实验、阶段门和放弃条件写入 `PLAN.md` 与 `RISKS.md`。
- 仅将用户明确选定的范围写入当前计划；未选路线不得伪装成承诺。
